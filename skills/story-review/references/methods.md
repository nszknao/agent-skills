# 診断の進め方

文章の目的を達成するために、内容と伝え方のどちらを変える必要があるかを判断する。固定の観点、目的別の追加観点、出力形式は本スキルの設計判断であり、研究で検証された尺度ではない。出典番号と確認範囲は sources.md に記載する。

## 1. 読者と目的から必要な内容を決める

「何について書いているか」と「読者に何を届けたいか」を分ける。同じ開発題材でも、経緯の共有、実装手順の説明、採用の提案、利用者の募集では必要な情報が変わる。

タイトル・冒頭・結びから目的を仮置きし、本文がその目的を果たすか確認する。複数の目的は成立し得るが、全ての目的を勝手に追加しない。未指定の目的が評価を変える場合だけ確認する。[W2, W3]

## 2. 内容の不足と伝え方の問題を分ける

| 状態 | 診断 | 改善の方向 |
| --- | --- | --- |
| 要点自体が競合する | 読者に何を残すかが定まっていない | 目的を確認し、主題を絞るか文章を分ける |
| 理解・判断に必要な情報がない | 材料の不足 | 必要な説明、具体例、条件、根拠を特定して補足を求める |
| 情報はあるが結論を支えない | 主張と根拠の不一致 | 主張を狭めるか、必要な証拠を確認する |
| 情報はあるが関係が伝わらない | 構成・説明の問題 | 配置、つながり、比較、説明の粒度を変える |
| 内容・構成は成立し文だけが曖昧 | 表現の問題 | 主語、指示語、用語、文の長さ等を局所修正する |

内容・論証・構成の大きな問題を、文単位の編集より先に検討する。[W2] どの原稿にも内容不足があるとは限らない。既存材料で目的を果たしていれば、その根拠を示して保つ。

**例**：「一週間の試用で作業が楽になった。全チームに導入すべきだ。」

- 自分の試用経験を共有するなら、観察した範囲に戻す修正ができる。
- 導入提案なら、比較条件や費用、他のチームでも成立する条件が判断材料になり得る。全部を必須項目にせず、結論を左右するものを選ぶ。
- 結論を冒頭へ動かしても、主張を支える材料の不足は解消しない。

## 3. 有効な指摘かを確認する

候補ごとに、原文の箇所、困る読者、妨げられる理解・判断・実行を結びつける。「追加できる話題」だけでは不足の根拠にならない。

- 本文の他の箇所を見て、既に説明されていないか確認する。
- 指摘に反する材料も見る。冒頭と結びの反復は重複か、読後に要点を再確認する働きか。
- 読者や目的を仮定した指摘はその条件を付ける。単なる好みや別案を要修正にしない。
- 未完成の開発記録に実績を要求せず、現状と今後の仮説を区別できるかを見る。
- 技術名を列挙した文章でも、概要を伝える目的なら採用理由の詳細は必須ではない。判断の経緯を共有する目的なら、理由の不足が重要になり得る。

修正の優先度は件数ではなく、中心的な目的をどれだけ妨げるかと、判断の確かさで決める。並べ替えが最も有効なら選んでよいが、内容の検討を飛ばす理由にはしない。

## 4. 経験や出来事を扱う箇所に物語論を使う

文章全体を物語にする必要はない。体験談や判断の経緯がある場合に、次を共通観点C2〜C6の診断へ利用する。[N1–N4, E1]

- 出来事の実際の順序と、本文で示す順序を分ける。結果から書くことは欠点ではない。
- 本文のその時点までに読者が何を知るかを確認する。後半を読んだ知識で前半の説明を補っていないか見る。
- 原文に示された事実と、書き手の推測や他人の内心を区別する。
- 詳細、要約、省略の役割を比較する。具体的な場面や葛藤を全箇所に追加しない。

個別の経験は説明を助けるが、一般的な主張の証明にはならない。小さな変化、未解決、失敗にも共有する意味はあり、成功談へ直さない。

## 5. 長さ・知識・掲載条件を適用に反映する

理解に必要な説明は、読者の既有知識や情報同士の関係によって変わる。[C1–C3] 字数だけで短文と長文の合格基準を分けない。

- 圧縮した文は、対象読者が省略を補えるか確認する。
- 節が増えれば、各節の役割と離れた情報の接続を確認する。
- 走査読みや途中再開が想定されるなら、見出しと必要な再導入が助けるかを見る。[W1]
- 同じサービスにも複数の掲載形式がある。媒体名から文字数や読まれ方を固定しない。[P1]

簡潔さのために詳細を絞ることと、正確さを下げることを混同しない。「試した範囲では」を削って一般化するのではなく、重要な条件を残し、扱う話題を絞る。

## 6. 判断を検証できる形で出す

観点ごとに原文の根拠と評価を示し、優先する修正と対応させる。参考資料を大量に読んだことや長時間の推論は、レビューの有用性を保証しない。作業の詳細な思考過程ではなく、読者が確かめられる判断の理由を出す。

共通表は確認範囲を見せる仕組みであり、欠点を完全に発見した保証ではない。外部事実の検証、画像の視覚評価、実読者への効果測定を行っていない場合は、その範囲を明確にする。
