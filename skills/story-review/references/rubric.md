# 評価の観点

観点は「何を評価するか」、根拠は「この原稿のどこから判断したか」である。題材が変わっても共通観点と目的別の追加観点の名前・定義を変えない。「ニュースの選び方」「料理の作り方」等を独自の評価軸にしない。

## 共通7観点

この名前と順序で全て評価し、出力する。問題なしの項目も省略しない。

| ID | 観点 | 確認すること | 隣の観点との区別 |
| --- | --- | --- | --- |
| C1 | 読者と目的に合っているか | 想定読者が知りたいことに応え、文章の目的を果たしているか | 誰に何を届けるかを見る。目的不明を文章の欠点にしない |
| C2 | 伝えたいことが明確か | 主題や重要な点が分かり、途中でぶれていないか | 中心となる内容を見る。明示的な結論文は必須ではない |
| C3 | 情報に過不足がないか | 理解や判断に必要な情報があり、不要な説明が増えていないか | 材料があるかを見る。既にある情報の伝え方はC6 |
| C4 | 事実や主張に無理がないか | 事実・推測・仮説を区別でき、主張に根拠があり、論理が飛躍していないか | 主張がどこまで言えるかを見る。本文だけの検討と外部検証を区別する |
| C5 | 構成が分かりやすいか | 情報の順序、段落の役割、前後のつながりが理解を助けているか | 全体や部分の配置・関係を見る。語句だけの問題はC7 |
| C6 | 説明が分かりやすいか | 用語、具体例、説明の細かさが想定読者に合っているか | ある情報を理解できる形で伝えているかを見る |
| C7 | 文体や表現が適切か | 語句や文が明瞭で、語調が目的と書き手の意図に合っているか | 文単位の明瞭さ・語調を見る。全てを無個性な文体にそろえない |

### 評価の意味

| 評価 | 使用する条件 |
| --- | --- |
| 問題なし | 確認した範囲で目的を妨げる問題がない。機能している箇所を根拠として示す |
| 改善余地 | 意味は通るが、目的に照らして改善の効果が見込める。任意か条件付きかを明記する |
| 要修正 | 矛盾、必要情報の欠落、過大な主張などが、意図した理解・判断・実行を妨げる |
| 材料不足 | 読者・目的・本文等の不足で評価できない。何が分かれば判断できるかを示す |
| 対象外 | 指定範囲や文章の性質上、観点が適用されない。理由を示す |

外部の裏取りをしていないことだけでC4全体を「材料不足」にしない。本文内の論理・主張の範囲を評価し、外部事実は未検証と明記する。ただし結論を左右する根拠を確認できない場合は、そこを材料不足として残す。「問題なし」は内容の真偽を認証した意味ではない。

## 目的別の追加観点

目的から必要なものだけ選び、以下の名前をそのまま別表に使う。題材・媒体名から自動選択しない。複数の目的が明示されていれば併用する。選ばなかった項目を毎回列挙する必要はない。

| ID | 適用する目的 | 追加観点 | 確認すること |
| --- | --- | --- | --- |
| P1 | 読者に手順を実行してもらう | 読者が手順を実行できるか | 対象環境、前提、入力、操作、結果の確かめ方が目的に足りるか。概要紹介には適用しない |
| P2 | 意見や提案に納得してもらう | 重要な反論に答えているか | 想定読者の判断を変え得る反論・代替説明・適用限界を扱っているか。あらゆる反論の列挙は求めない |
| P3 | 商品・サービスの利用を判断してもらう | 利用判断に必要な情報があるか | 対象者、役立つ場面、必要な条件や制約が判断に足りるか。機能の開発記録だけには適用しない |
| P4 | 申込・試用・参加等の行動を促す | 次に何をすればよいか分かるか | 求める行動と方法が分かるか。実行できないリンク等は未確認とする。情報共有だけにCTAを要求しない |

**追加なしでよい例**：開発の経緯を伝える記事、仕組みの解説、日々の経験の共有。技術の話でもP1は必須ではなく、商品名があってもP3・P4は必須ではない。追加観点で発見した問題は共通観点との関係を示してよいが、別の問題として数を水増ししない。

## 掲載条件による適用の違い

条件は評価軸ではない。確認した条件を、上の観点の判定に反映する。

| 確認できた条件 | 主に使う観点 | 判定時の注意 |
| --- | --- | --- |
| 初見の読者がタイムラインで読む単発投稿 | C1・C2・C3・C5 | 冒頭で話題や読む理由がつかめ、その投稿が担う意味が通るか。背景を全て説明する必要はない |
| 連投・折り畳み・リンク先への遷移がある | C3・C5 | 見える単位ごとの役割、切り出された際の意味、全体へのつながりを確認する |
| 字数制約が厳しい | C2・C3・C4・C7 | 主題を絞り、留保を残す。制約に収まったことだけを合格にしない |
| 節が多い、前提の説明と使用箇所が離れる | C3・C5・C6 | 各節の役割と接続、必要な再提示を確認する。長さ自体を欠点にしない |
| 読者が専門知識を持つ／持たない | C1・C3・C6 | 既有知識に合わせて省略や用語説明の必要性を判断する |

## 根拠の書き方

- 不適切：独自の観点「タイマーの効果」を作り、「よく伝わる」とだけ評価する。
- 適切：共通観点「事実や主張に無理がないか」に、「『3日使って予定を守れた』から『誰でも習慣になる』への一般化は、個人の短期経験だけでは支えられない」と書く。
- 適切：「情報に過不足がないか」に、「作業時間の記録方法は説明済み。読者に再現を求める記事なら対象環境が必要だが、開発経緯の共有なら必須ではない」と目的による違いを書く。

## 出力前の点検

- 共通7観点が同じ名前・順序でそろい、各項目に原文の根拠があるか。
- 題材を別のものへ置き換えても、観点名と定義は変わらないか。
- 追加観点は定義済みのものか。選択理由は文章の目的か。
- 内容に関わる不足と、並べ替えや語句の修正で解決できる問題を区別したか。
- 足りないとした情報が原稿の別の箇所に既にないか。
- 不明な目的や未確認の読者反応を、原稿の欠点として断定していないか。
- 全体表と優先する修正が対応し、必須の修正と任意の改善を分けたか。
